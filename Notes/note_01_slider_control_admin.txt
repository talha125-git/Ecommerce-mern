===================================================================================
                        NOTE 01: HERO SLIDER CONTROL SYSTEM
                           Architecture & Technical Notes
===================================================================================

[ SYSTEM OVERVIEW ]
-----------------------------------------------------------------------------------
This system empowers the Admin to fully manage the Storefront Hero Slider (titles, 
subtitles, badges, action buttons, gradient overlays, and background images) in 
real-time across all devices (Desktop, Mobile, Localhost, and Vercel Production).


[ TECH STACK & METHODOLOGY ]
-----------------------------------------------------------------------------------
Component        Technology / Method           Role & Function
-----------------------------------------------------------------------------------
Database         MongoDB Atlas + Mongoose      Master cloud storage for slide data
Image Hosting    Cloudinary CDN                Uploads images & returns HTTPS URLs
Backend API      Node.js + Express             API endpoints (/api/slides)
Admin Panel      React (SliderTab.jsx)         CMS UI to edit & manage slides
Storefront       React (HeroSlider.jsx)        Renders live slides to customers
-----------------------------------------------------------------------------------

[ DETAILED IMPLEMENTATION STEPS ]
-----------------------------------------------------------------------------------
1. IMAGE UPLOADING (Cloudinary CDN):
   - Admin selects an image file from their computer.
   - Frontend reads it as Base64 and sends it to `POST /api/upload-slider-image`.
   - Express backend uploads the Base64 image to Cloudinary folder `ecommerce/sliders`.
   - Cloudinary returns a permanent HTTPS URL (`https://res.cloudinary.com/...`).
   - Fallback: If Cloudinary keys are missing, backend falls back to Base64 so app 
     never crashes on local testing.

2. DATABASE PERSISTENCE (MongoDB Atlas):
   - Admin edits titles, text, gradients, or button links and clicks "Save Slider Changes".
   - Frontend sends the updated slide array to `POST /api/slides`.
   - Backend executes Mongoose `findOneAndUpdate` with `{ key: "hero_slider" }` and 
     `upsert: true`.
   - Data is stored centrally in MongoDB Atlas cloud database.

3. STOREFRONT RENDERING (HeroSlider.jsx):
   - On page load (`useEffect`), `HeroSlider.jsx` calls `GET /api/slides`.
   - Updates React state `setSlides(res.data.slides)` dynamically.
   - Also syncs to `localStorage` as secondary cache for instant client rendering.
   - Listens to window custom event `'hero-slides-updated'` for same-tab updates.
